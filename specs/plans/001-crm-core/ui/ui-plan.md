# 前端 / UI 與靜態雛形規劃

## 介面範圍

- 目標系統介面：`CRM 核心網頁操作介面（包含客戶管理、聯絡歷程、銷售機會與銷售管線）`
- 需求來源：`使用者故事 1 至 4、FR-001 至 FR-018 與 NFR-001 至 NFR-004`
- 上游依據：`specs/plans/001-crm-core/spec.md` 與 `specs/plans/001-crm-core/features/acceptance/*.feature`
- 產出順序：`先定稿 ui/ui-plan.md，再依這份 plan 產出可操作之 HTML 靜態雛形（ui/index.html、ui/customers.html、ui/customer-detail.html、ui/opportunity-detail.html）。`

## 視覺方向

- 風格來源：`現代專業 SaaS B2B CRM 設計語言（參考 Linear, Stripe Dashboard 與 HubSpot 風格），以高資訊密度、乾淨層級與流暢操作為導向。`
- 本次風格結論：`深邃沉穩背景搭配精緻卡片、鮮明且語意明確的階段顏色標籤（潛在-藍、已聯繫-紫、提案中-橙、已成交-綠、已失敗-紅），強調數據可讀性與操作敏捷度。`
- 視覺重點：`銷售階段視覺進度條、管線 Kanban 欄位金額統計、客戶互動時間軸（倒序排列）與醒目的下一步行動警示卡片。`
- 審美原則：`畫面維持真實產品體驗，不使用說明文件口吻，不把分析備註或除錯訊息寫入產品畫面，所有按鈕與狀態切換皆提供即時視覺回饋。`

## 畫面與流程

### 1. `銷售管線綜覽入口畫面`

- 對應雛形檔案：`ui/index.html`
- 主要目的：`作為 CRM 系統首頁入口，提供銷售管線看板（Pipeline Kanban），依階段呈現機會、負責人與總額，並提供角色切換以驗證管線權限差異。`
- 進入條件：`使用者開啟系統首頁（預設以業務主管 Carol 身份檢視全團隊管線）。`
- 主要操作：`檢視各階段機會卡片、切換角色（Carol 主管全覽 vs Alice 一般業務個人視角）、點擊機會卡片進入機會詳情、點擊導覽列切換至客戶管理。`
- 成功流轉：`點擊機會卡片導向 ui/opportunity-detail.html；點擊導覽列「客戶名單」導向 ui/customers.html。`
- 失敗回饋：`切換為一般業務時，非負責之機會即時隱藏；若查詢無資料則呈現乾淨的空狀態引導。`

### 2. `客戶與公司資料管理畫面`

- 對應雛形檔案：`ui/customers.html`
- 主要目的：`管理企業組織與客戶聯絡人清單，支援快速建立公司、新增聯絡人與關鍵資訊檢索。`
- 進入條件：`從導覽列點選「客戶與公司」進入。`
- 主要操作：`瀏覽公司與聯絡人列表、點選「+ 建立公司」或「+ 新增聯絡人」互動彈窗、點擊特定客戶進入客戶詳細歷程。`
- 成功流轉：`點擊「水球軟體 / 王大明」即時導向 ui/customer-detail.html。`
- 失敗回饋：`若未填寫必填欄位（公司名稱、聯絡人姓名、Email 格式錯誤），即時顯示表單驗證紅字提示。`

### 3. `客戶歷程與聯絡記錄畫面`

- 對應雛形檔案：`ui/customer-detail.html`
- 主要目的：`展示特定客戶之完整資訊、最近下一步行動排程，以及依時間倒序呈現的互動時間軸，並提供即時記錄聯絡表單。`
- 進入條件：`由客戶列表點擊特定客戶進入。`
- 主要操作：`填寫聯絡記錄表單（方式、摘要、下一步行動內容、預計執行日）並送出、檢視歷史時間軸、從關聯機會直接跳轉至商機頁。`
- 成功流轉：`點擊「儲存聯絡紀錄」後，時間軸頂部立即新增該筆互動，並同步更新畫面最上方之「下一步行動」提醒卡。`
- 失敗回饋：`若未輸入內容摘要或日期為過去無效值，提示錯誤並保留表單輸入內容。`

### 4. `銷售機會與階段推進畫面`

- 對應雛形檔案：`ui/opportunity-detail.html`
- 主要目的：`展示商機完整細節（金額、預計成交日、關聯公司與客戶），並提供階段推進器（Stage Stepper）與權限驗證操作。`
- 進入條件：`由管線看板或客戶詳情頁點選特定銷售機會進入。`
- 主要操作：`點擊推進至「提案中」或標記「已成交」、切換當前登入者身分（負責人 Alice vs 非負責人 Bob）驗證越權操作攔截。`
- 成功流轉：`當以 Alice（負責人）身份操作時，階段推進成功，進度條切換至「提案中」並記錄操作軌跡。`
- 失敗回饋：`當切換為 Bob（非負責人且非主管）身份點擊推進時，系統立即彈出「權限不足：您不是本銷售機會負責人或主管，無法修改階段」之阻擋警告。`

## 互動與假資料原則

- 假資料策略：`全面使用驗收情境規格之真實業務資料：公司「水球軟體」、「鼎新科技」、「宏通通訊」；客戶「王大明（技術長）」；業務人員「Alice」、「Bob」；主管「Carol」；機會「企業版授權合約（NT$300,000）」等。`
- 互動原則：`使用純原生 JavaScript 實現無伺服器端的流暢互動，包含表單即時插入清單、身分切換過濾清單、權限錯誤彈窗、階段進度條動態響應。`
- 內容原則：`所有文字與指標皆採標準專業 CRM 術語，杜絕出現「這是一個測試按鈕」或開發 TODO 字樣。`

## 狀態與資訊揭露

- 使用者可見資訊：`公司名稱、統一編號、聯絡人姓名、Email、職稱、電話、聯絡紀錄內容、下一步行動日程、銷售階段、機會金額、負責業務。`
- 必須隱藏資訊：`一般業務不得看到非自身負責機會之敏感業績數據（透過角色切換模擬）；未授權成員之管理後台操作入口。`
- 主要 UI 狀態：`預設管線檢視、個人管線檢視、表單新增互動彈窗、表單驗證錯誤、階段推進成功通知、越權操作攔截警告。`
- 角色或權限差異：`業務主管 Carol 具備全管線讀取與強制變更權限；一般業務 Alice 僅能修改自身負責之商機與客戶。`

## 驗證與錯誤回饋

- 輸入驗證：`公司名稱與聯絡人姓名必填；Email 必須包含 @ 格式；預估金額限制為大於 0 之正整數；成交日期必須為未來有效日期。`
- 狀態衝突處理：`非負責人進行階段推進時，畫面保留現狀並以 Toast/Alert 顯示明確權限拒絕通知。`
- 使用者可理解錯誤訊息：`清楚標示原因，例如「請輸入有效的電子郵件地址」、「預估金額不可為負數」、「權限不足：非負責人不可推進階段」。`

## 靜態雛形輸出規劃

- 多頁入口：`固定以 ui/index.html 作為雛形主要入口（銷售管線與導覽中樞）。`
- 預計輸出檔案：
  1. `ui/index.html`：銷售管線看板首頁（Kanban 檢視、角色切換、總額統計）
  2. `ui/customers.html`：客戶與公司列表（公司與聯絡人清冊、建立彈窗）
  3. `ui/customer-detail.html`：客戶詳情（聯絡歷程時間軸、新增聯絡表單、下一步行動）
  4. `ui/opportunity-detail.html`：銷售機會詳情（階段推進器、權限防護模擬）
- 換頁原則：`所有頁面皆具備全域導覽列，能在「銷售管線」、「客戶與公司」與詳情頁之間自然雙向切換。`
- Review 目標：`PM 與利害害關係人能直接點擊瀏覽、模擬業務紀錄與主管綜覽之完整業務 Journey。`

## 前端實作切分建議

- 頁面 / 容器切分：`導覽列 (Global Navbar)、管線看板欄 (Pipeline Kanban Column)、時間軸元件 (Timeline View)、階段推進器 (Stage Stepper)。`
- 共用元件或區塊：`StatCard (統計數據卡)、Modal (建立視窗)、Toast (操作與錯誤反饋訊息)、RoleSwitcher (角色切換模擬器)。`
- 對後端契約的依賴：`Companies API、Contacts API、Interactions API、Opportunities API 與 Auth/Role API。`
- 驗收重點：`完全對齊 spec.md 與 features/acceptance/*.feature 定義之業務規則與例外拒絕情境。`
